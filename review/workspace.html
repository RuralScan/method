5.2 How to review

Review checks the extraction against its source. It does not approve a spatial model, a proposed investment or every other claim from the same paper.

5.2.1 Get connected

Sign in to GitHub. Open a finding and check the original passage before submitting a review. Votes, notes and GitHub names are public. Restricted sources stay in the source library.

5.2.2 Work through the queue

  1. Set your own GitHub handle in Review queue. Choose Other… if it is missing. This selector filters historical decisions. GitHub credits the account that creates the issue. Use practice, evidence type and search to narrow the queue.
  2. Start with To review: active findings you have not reviewed. Use AI-flagged, AI-passed or 2nd opinion to narrow that work. Kept, Queried and Dropped show your calls; My reviewed includes your history. Shortcuts set the visible sidebar filters, which you can refine. The Filters sidebar contains practice, evidence type, technical filters and dropped history. Site observations are deferred by default and can be included there. On small screens, open Filters above the findings.
  3. Read the claim and inspect its source. Check the page or table, units, context, practice and intended use. Open the source region or full paper when the excerpt lacks context. A restricted source may require the synced library or its SharePoint link; contact the library maintainer if access is missing.
  4. Keep when the extraction is faithful and relevant. Drop when it is unsuitable or incorrect: select a coded reason and explain it. Drop quarantines the record; it does not erase it. Query when clarification is needed: state what needs checking. A query is not approval.
  5. Review answers on the evidence card. Choose Answers ready to find returned answers, including findings you previously queried. Read the answer and source, then Keep, Drop or Query. The sidebar Follow-up filter also exposes waiting questions, conflicts and requested rechecks. There is no separate answer-approval step; deciding one record does not approve the other records sharing its answer.
  6. Choose Keep, Drop or Query on the card. Your decision is saved on this device and the queue moves to the next finding. Choose Submit all my decisions, then create the GitHub issue. Its number is your receipt. Find it through My reviewed.

5.2.3 If something needs attention

  • Missing sources: hydrate the corpus and use Recheck. A source-cache presence count is not a completed quote check; submission runs the provenance guardrail.
  • Missing extraction: use Report missing evidence under More actions and identify the source and location.
  • Submission failed: decisions remain saved locally. Read the reported error before retrying; do not start a second submission while one is still running.
  • Interface feedback: use Feedback in the dashboard header. These notes stay in this browser at this address until exported; they do not Keep, Drop, Query or submit an evidence decision.
