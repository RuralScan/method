How people and AI build a RuralScan recipe

A recipe starts with a question about one practice family. An assistant can find sources, propose evidence records and flag conflicts. A reviewer decides what each passage supports. The compiler reads the registered evidence, method definitions and recorded decisions to produce candidate analytical tables.

Set up and rehearse a run

Use Git and Python 3.10 or newer for the offline screening example. For the review preview and full terrace replay, install uv and make Python 3.12 available. Start in a private working directory. The first clone, dependency installation and full replay need network access.

git clone https://github.com/RuralScan/evidence.git
cd evidence
git checkout --detach e47349055f1c34a5dd755b37ab9c4e7012882823
work=$(mktemp -d)
python3 workflows/discovery/screen.py stage workflows/discovery/example/plan.json \
  workflows/discovery/example/decisions.json --out "$work/screen"
cat "$work/screen/report.md"

The frozen exercise returns three distinct records, three screened and one included for reuse. A replay adds no search coverage. To rehearse review, run the following from the same checkout.

uv run --python 3.12 --locked --script workflows/review_preview/preview.py --example

The preview uses disposable records. Expect one keep, one recoverable drop, one unresolved conflict and a byte-identical second replay. To trace a real source, the full terrace replay downloads the manual, stages the passage and independently rebuilds the historical row from its original inputs.

Add a practice or family

In the producing CIAT checkout, start with a stable practice ID and the draft recipe scaffold. Use the manifest for T0 identity and analytical table headers. Document the limiting factor shared by each proposed family, its member practices and its spatial product. Ask the scientific reviewer to check the grouping and define the first search question. Change search terms or extend coverage

Copy the discovery plan to a private run directory. Set a fresh run ID, practice, family, one table, one process and inclusion criteria. Change the query in the capture step, record the language and limits, and list the resulting capture files in the new plan. Generate a fresh worksheet against those inputs. Inspect borderline exclusions and duplicate records before staging. Register actual per-scope counts and retain the earlier terms, results and exclusions. Capture, worksheet and staging commands

Update an existing practice

Start at its recipe row. Follow the family, variable and evidence IDs to the source passage and existing review history. Record what changed: source edition, interpretation, contextual applicability or calibration. Stage new evidence or propose an audited correction to the existing ID. Give the reviewer the old and proposed values, units, locator and rationale. Preserve earlier decisions and holds. After review, rebuild the affected recipe against pinned inputs and compare row IDs, scope, values and evidence links before issuing a new candidate. Human review and its effect on later agents

For an authorised live review, start uv run python3 -m nbs_ruralscan.schema_tools.review_server from the CIAT checkout and open http://localhost:8765/dashboard.html. Choose QA/QC. Select a card under To review. Compare the excerpt with the original page, table headings, units, family and role. Inspect earlier decisions and source context before voting.

  • Keep a supported claim in its recorded scope. A claim about observed use can be kept while the numerical calibration remains held.
  • Drop an unsupported claim with a coded reason. Its retained record allows reopening. Reclassify species-specific evidence with its taxon when that is the appropriate scope.
  • Query an ambiguous interpretation. In Waiting for answers, track the question. Check the source-backed answer on the card and make the decision. Disagreements stay open for resolution.

Use the live dashboard’s Apply and submit action for agreed decisions. For the next assisted run, give the agent the current ruleset, the relevant reviewed records, the permitted family and role, and any exclusions or calibration holds. Require a page-anchored reason for a proposed change. Route a challenge back to review. After a sweep, examine coded defects, update the versioned instructions and regression check for recurring errors, and record which feedback was incorporated.
