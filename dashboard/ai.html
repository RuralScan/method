Author a scientific proposal

  1. Prepare the authorised practice/table input packet and skill snapshot.
  2. Read source-provenanced evidence and account for every candidate, including exclusions, shared origins and holds.
  3. Assess routing, compatibility, dependence, uncertainty and sensitivity. Author direction, strength, evidence level, agreement, confidence and applicability with scientific rationale.
  4. Write authoritative CSV rows, explicit replacements or withdrawals, and a before/after comparison. Preserve actual model, prompt, skill and settings provenance.
  5. Validate and commit the immutable proposal. Passing checks is not scientific acceptance.

Accept exact outputs

An eligible human reviewer records an original acceptance or hold receipt bound to the proposal's exact hash and Git revision. Evidence review and software approval are separate from accepting new scientific judgments. Changed evidence, unresolved holds or changed accepted values block publication until reviewed again. A rating hold also blocks the relevant accepted output.

Replay accepted values

Packages contain current accepted outputs and withdrawal provenance. Runtime verifies an independently pinned manifest and returns the explicitly selected record unchanged. Missing accepted cells remain gaps; historical rows never fill them automatically. Reproducibility means preserving accepted bytes and their audit trail, not assuming a fresh AI run will agree.
